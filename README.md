# AstrBot Dota2 助手插件修改加强版

Dota2 数据查询插件，支持自然语言触发，通过 LLM 工具自动调用 OpenDota API 返回结果。
查询结果默认渲染为**白底图片卡片**（背景 `#ffffff`、分栏目标题深蓝色 `#1e3a8a`、详情正文黑色），也支持纯文本输出。

## 功能

> **唤醒规则**：消息里必须出现**刀塔标识**（刀塔 / 刀塔2 / dota / dota2）、
> **8~10 位比赛编号**、或**明确的刀塔英雄名**，插件才会被唤醒。
> 只说「分析比赛」「查战绩」「怎么出装」而没有上述信号时不会触发，
> 这样可与其他游戏（王者荣耀、英雄联盟等）的查询插件区分开。

| 功能 | 自然语言示例 | 命令 |
|------|-------------|------|
| 玩家查询 | "查一下 miracle 的刀塔战绩" | `/dota player miracle` |
| 我的战绩 | "查询我的最近一场刀塔比赛" | 需先绑定 |
| 英雄查询 | "刀塔水人属性是什么" | `/dota hero 水人` |
| 出装推荐 | "水人怎么出装" | - |
| 物品查询 | "跳刀多少钱" | - |
| 比赛详情 | "分析刀塔比赛 8831125663" / "8831125663" | `/dota match 8831125663` |
| 实时比赛 | "现在有什么刀塔比赛在打" | `/dota live` |
| 职业赛事 | "最近刀塔 TI 结果" | `/dota pro` |
| 英雄列表 | "有哪些刀塔力量英雄" | - |

## 图片输出

**所有查询功能默认返回图片卡片**，无需任何参数。卡片为纯白底
（背景 `#ffffff`、分栏目标题深蓝色 `#1e3a8a`、详情正文黑色 `#000000`、
胜负标记着色），在深色与浅色聊天背景下都清晰可读。

### 输出模式

默认返回图片卡片。也可以在**插件配置页把「图片回复」关掉**（`enable_image_output`），
此时所有查询都改为直接返回 **Markdown 文档**（纯文字）——
数据可以选中复制、可以搜索，代价是没有卡片样式。

| 方式 | 写法 | 效果 |
|------|------|------|
| 默认（推荐） | `糖糖 查一下奇迹哥的刀塔战绩` | 直接返回图片卡片 |
| 单次强制纯文本 | `糖糖 查一下奇迹哥的刀塔战绩 --text` | 本次返回 Markdown，不生成图片 |
| 单次强制出图 | `糖糖 查一下奇迹哥的刀塔战绩 --image` | 即使配置里关了图片，本次也出图 |
| 绑定 / 解绑 | `/dota bind 899428504` | 命令结果保持纯文本，不生成图片 |

「图片回复」关闭后，`/dota` 命令也默认走文本；想临时看图加 `--image` 即可。
LLM 也可通过工具参数 `text_only=true` 要求纯文本（当用户说"不要图片""纯文字"时会自动传入）。

### 卡片末尾的点评随查询内容变化

卡片最下方的评价区块**按查询种类换文案**，保证点评与上方那份数据对得上：

| 查询 | 评价区块标题 | 内容 |
|------|--------------|------|
| **具体某一局**（比赛详情） | 「综合分析」 | 三点式赛后总结（见下） |
| 玩家资料 / 我的战绩 | 「点评」 | 一段话讲近期状态、点名具体英雄 |
| 英雄资料 | 「点评」 | 一段话讲定位、强势期，只用卡上的胜率 |
| 英雄列表 | 「点评」 | 一段话概述名单构成（**卡上没有数值，不会编造胜率**） |
| 英雄出装 | 「点评」 | 一段话讲各阶段出装思路与主流选择 |
| 物品 | 「点评」 | 一段话讲适用英雄、局势与性价比 |
| 实时比赛 | 「点评」 | 一段话指出哪几场值得看 |
| 职业比赛 | 「点评」 | 一段话概括赛事看点与值得回看的场次 |

种类由卡片的 `#` 标题识别（`# 比赛详情` / `# 玩家资料：…` 等），
所以**一轮里同时查了对局和别的，按对局处理**（三点式信息量最大）。

### 只有具体对局才写三点式赛后总结

比赛详情卡里有双方十人的数据（天辉/夜魇各五人、经济/KDA/参战率），
因此只有它才写三点式总结 —— 总结在卡片上固定渲染成**三个小栏目**，
小标题由插件补齐、内容来自模型：

1. **天辉方的表现** —— 从**天辉五名玩家**里挑 1-2 人点评，给出四项数据：
   **经济、经验、KDA、参战率**，说明他好/差在哪，
   最后一句话点明天辉输赢的关键；
2. **夜魇方的表现** —— 同样挑 1-2 人，给出四项数据并点评，
   最后一句话点明夜魇输赢的关键；
3. **一句话总结** —— 用一句话点明整场比赛输赢的关键在哪儿。

#### 总结数据来自录像解析（OpenDota）

具体某一局的总结**不再**只喂「卡片上的 KDA/经济」，而是向 OpenDota
**申请录像解析**，用解析出的动态数据来写：

* **关键目标时间线** —— 一血、推塔/兵营、击杀肉山、拾取不朽盾各发生在何时、属哪方；
* **主要团战** —— 规模最大的几场团战，以及哪方占优（按双方金钱收益之和判断）；
* **经济曲线拐点** —— 天辉领先峰值、最深落后各出现在第几分钟；
* **各玩家录像级表现** —— 对线效率、百分位 benchmark（>85 分位算亮眼、<30 分位算落后）。

这样总结能讲清「**这场是怎么赢/输的**」—— 前期靠一血和先塔打开局面、
哪波团战奠定胜负、经济从何时拉开、谁的对线打穿 —— 而不只是复述静态数字。

**解析是异步的**（OpenDota 官方说数分钟、实测常见 5~10 分钟）：

* **已解析**的比赛：同步生成总结、直接出图，无需等待；
* **未解析**的比赛：先发一条「录像正在解析中，请稍候…」，后台提交解析并轮询，
  完成后把**对战数据与点评合成同一张卡片**补发到原会话
  （对战信息与赛后点评始终同一张卡，不分开发）。
* 超时（默认 720 秒，`replay_parse_timeout`）则放弃点评、只补发对战数据卡，
  保证用户至少拿到数据。

可整体关闭（`enable_replay_summary`）退回旧逻辑：直接把卡片文字喂模型写总结，
无需等待解析，但只有静态数字、讲不出比赛节奏。

#### 只点评突出的和落后的

**不逐一点评每个英雄**：每方只挑最有信息量的 **1-2 人**，优先这两类：

* **特别突出** —— 经济/经验大幅领先全队、KDA 漂亮、或参战率很高（积极开团）；
* **特别落后** —— 经济明显垫底、KDA 很差、或参战率明显低于 100%（避战）。

某队五人表现平平均匀时，就用一句话概括整体，**不为了凑数人人写一句**。
10 个英雄各写一句既没有重点，也会把卡片撑得很长。

全文（三个栏目正文相加）默认控制在 **500 字**以内（可配置，见
`summary_max_chars`）：这个长度足够讲清「谁突出、为什么」，
再长就会退回「人人一句」的流水账。
模型偶尔仍会写超，此时插件**按栏目分摊着精简**，而不是拦腰截断 ——
先截断的话，被砍掉的永远是结尾的「一句话总结」，
读者看到的就是「总结显示不完整」。
精简时优先保全「一句话总结」和「点名英雄」，再按句末标点收缩天辉/夜魇两栏。

小标题（`### 天辉方的表现` 等）**由插件在拼接卡片时写入**，不依赖模型自觉：
实测模型有时漏写、有时改写成「天辉方胜负关键」这类旧写法，
插件两种都能识别并统一成上述三个标题。

**其余查询一律不设小标题**，评价区块只有一段正文 —— 近期战绩、英雄档案
这些卡片里没有分队也没有十名玩家，硬套「天辉方的表现」只会写出与上方列表
矛盾的内容。模型偶尔仍会自己写 `###` 小标题，插件会把标记去掉、只留文字。

定位只认**行首关键词**，且标题跟着内容走而不是按顺序编号 ——
模型整段漏掉某一栏时，剩下几栏的标题仍然正确（漏掉的栏就不出现），
不会出现「一句话总结」的正文挂在「夜魇方的表现」下面这种张冠李戴。
一段都认不出时**不硬套标题**（宁可只保留正文加粗）；
只认出一段时，还得确认它确实带标题标记（`#` 或 `1.` 序号），
免得把「天辉前期压制力不足」这样的正文误当成栏目标题。

若在提问中点名了某个英雄（例如「8831125663 我朋友用的火猫怎么样」），
会在三点之后**额外单独点评一段**，同样渲染成一个小栏目「点名英雄」，
不会被并进「一句话总结」（否则那个栏目就名不副实了）。

#### 四项数据分别看什么

| 数据 | 卡片字段 | 说明 |
|------|----------|------|
| 经济 | 金钱 / GPM | 金钱用 `k` 简写（如 `18.6k`） |
| 经验 | XPM | 每分钟经验 |
| KDA | 击杀 / 死亡 / 助攻 | 标题行已高亮 |
| 参战率 | 参战 | 见下 |

**参战率的算法**：每次**击杀、助攻、死亡**都意味着与对手发生过一次战斗接触，
三者相加即该玩家的「参战次数」。以本队五人的参战次数之和为分母、
再乘队伍人数，使 **100% = 与队友平均水平持平**：

* 高于 100% —— 比队友更好战，积极参与战斗；
* 明显低于 100% —— 击杀、助攻、死亡都偏少，即**避战选手**
  （只顾刷钱、不参与战斗）。

之所以不按「参战团战场次 / 团战总场次」计算：团战数据（`teamfights`）
只在 OpenDota **已解析**的比赛里才返回，实测普通玩家近期对局的解析率
仅约 7%，绝大多数比赛会算不出来。只用 K/A/D 则不依赖比赛是否被解析，
任何对局都能算。

### 点评在图片最下方

插件会**自己调用本机对话大模型**写评价：具体对局按上述三个要点写复盘，
其余查询写一段与该份数据对应的点评。评价以 **「综合分析」**（对局）
或 **「点评」**（其余查询）为标题，作为卡片的**最后一个区块**渲染进图片
（暖色底 + 左侧色条），而不是作为另一条消息发送。
因此评价始终位于图片最底部，不会与上方表格/图表重叠。

#### 可读性

总结正文用 **20px**（与分栏目标题同号，比普通正文的 17px 明显大一圈），
行距 1.72，宁可把图片拉长也要保证手机上能看清。
三个小栏目的标题用 **19px 深蓝加粗**：比它统领的正文略小一号，
层级才不会反过来。

正文里的**英雄名加粗并变深蓝**，字号与正文一致（不放大）：
早期版本会把英雄名同时加粗并**再放大 8%**，同一段里字号忽大忽小、
连读时反而难读，现已去掉放大、只保留加粗。
英雄名由插件从卡片头像的 `alt` 里提取后确定性地加粗，
不依赖模型自觉——实测同一份提示词下模型时粗时不粗。
两条渲染路径（网络 t2i / 本地 Pillow）都执行同一套加粗，外观一致。

总结**一律用英雄名指代玩家**，不出现昵称、账号 ID 或「匿名玩家」：
昵称经常是乱码、空白或纯符号，英雄名才是读者能对上号的标识。

对战数据里每人**第一行（等级 / 玩家名 / KDA）整行加粗**，
而「金钱 / GPM / XPM / 正补」那一行的**数值不加粗** ——
整行八项数值都加粗会比正文更难扫读，第一行已经承担了强调。

这里说的「整行加粗」是两条路径对齐后的结果：网络模板的 `h3` 本就是
`font-weight:600`，等级、分隔符、玩家名、KDA 共用同一个偏重字重
（实测 600 与 700 渲染完全一致，所以玩家名上那对 `**` 在网络路径里并无
额外效果）。本地 Pillow 若只按 `**` 描边，等级与分隔符就会掉回常规字重，
同一条标题行在两条路径下字重不同。现在本地路径对标题行整行描边，
`**` 只保留为「哪一段是强调」的语义标记。

**图片高度不设上限**：总结越长卡片越高，两条路径都会把内容完整画进去。
实测网络 t2i 在 13451px 高度仍能完整产出（10 人战报 + 约 1.4 万字总结），
因此不需要为「装不下」而牺牲内容 —— 控制字数纯粹是为了可读性。
反过来说，如果总结看起来没写全，原因在生成端（模型写超后按栏目精简），
不在渲染端。

卡片最底部还有一条**横跨整宽的波浪装饰纹**（网络渲染为内联 SVG、
本地渲染为 Pillow 绘制的正弦波），两个渲染路径保持一致。

由插件自己调模型，而不是直接用主对话模型的回复，原因是：

- Agent 这一轮可能因上游故障（如 503、工具调用序列损坏）直接报错，
  那样图片底部就没有总结；
- 部分平台的回复会被其它插件改写，拿到的不一定是原始点评；
- 插件自己调模型时输入是**结构化的卡片数据**，总结质量更稳定。

模型调用失败、超时或返回空文本时，自动回退到 Agent 本轮的回复文字，
保证「图片一定有总结」这条底线不破。相关开关见[配置](#配置)。

实现上，出图由 `on_decorating_result` 钩子在 LLM 产出最终回复**之后**完成：
工具只把卡片数据暂存到事件上，钩子再调模型写总结并把「数据 + 总结」合成一张图。

### 对战数据的版式

每名玩家是一个三行区块，**英雄头像占据左侧并竖跨三行**，右侧才是其它数据：

```
## 天辉 获胜 · 击杀 41          ← 分队标题：胜负 + 团队总击杀

┌────────┐   Lv.25 · 玩家昵称 · 12/6/12    ← 第一行：等级 / 玩家 ID / KDA（24px）
│ 英雄   │   金钱 18.6k｜GPM 631｜XPM 672｜正补 198｜伤害 25.0k｜参战 68%｜…
│ 立绘   │   装备：[图标] [图标] [图标] ＋ [中立物品]
└────────┘
```

第一行承载**等级、玩家 ID、KDA**，字号 24px（其余文字 17px），整行统一字号。
数据行按重要性排序（金钱/GPM/XPM/正补 → 伤害/参战 → 推塔/治疗），
万一放不下会从**末尾整项**丢弃而不是缩小字号 ——
同一张卡里所有玩家字号必须一致。昵称特别长时优先**截断昵称**并保留等级与 KDA。

**胜负写在分队标题上**，而不是每位玩家的行首：胜负是队伍的结果，
写十次既冗余又容易看串行。标题同时汇总该队**总击杀**（只取 kill 数）。

### 渲染方式

图片按以下顺序尝试渲染，任一环节失败都会自动降级，不会中断查询：

0. **图标先落本地**：装备图标与英雄立绘由插件自己下载并缓存
   （`core/icon_cache.py`，目录按「插件数据目录 → 插件 assets → 临时目录」探测），
   发给网络 t2i 前内联成 `data:` URI，本地渲染则直接读文件。
   这样**远端端点不需要访问 Valve CDN** —— 它的浏览器经常拉不到图，
   轻则图标位置空白，重则端点等图超时、整次渲染直接失败。
1. **网络 t2i**：调用 AstrBot 内置的文转图服务（`Star.html_render`，
   默认端点 `https://t2i.soulter.top/text2img`），排版质量最好。
2. **本地 Pillow**：网络不可用时用内置渲染器绘制等效卡片，
   版式与网络路径一致（真实图标 + 头像竖跨三行）。
   CJK 字体按字形覆盖自动探测（Noto Sans CJK / 文泉驿 / 微软雅黑 / pillowmd 自带字体），
   胜/负标记等 emoji 会自动切换到覆盖该字形的字体混排。
   图标或立绘读不到时退化为中文名文本，不会留下空框。
3. **纯文本**：以上都失败时回退为文本，保证用户至少能拿到数据。

渲染产物会写入 AstrBot 临时目录，并在会话结束时自动清理。

### 英雄名称

卡片中的英雄名统一为 **Valve 官方中文译名**（`Ember Spirit` → `灰烬之灵`、
`Windrunner` → `风行者`、`Outworld Destroyer` → `殁境神蚀者`）。

查询时中文官方名、中文俗称（火猫、水人）、英文名与内部名
（`npc_dota_hero_ember_spirit`）都能命中，均由 `core/hero_names.py` 统一处理。

## 绑定 Steam ID

```
/dota bind 899428504          # 32-bit Steam ID
/dota bind 76561198859694232  # 64-bit Steam ID
/dota unbind                  # 解除绑定
```

绑定后可以说"查一下我的刀塔战绩"直接查询，自然语言触发必须带上"刀塔"、"刀塔比赛"。

## 安装

1. 将插件目录放入 AstrBot 的 `data/plugins/` 目录
2. 安装依赖：`pip install -r requirements.txt`
3. 重启 AstrBot 或在插件管理页面重载

## 配置

在 AstrBot 插件管理页面可配置：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `default_language` | 英雄/物品名称默认语言 | `cn` |
| `enable_fallback_commands` | 是否启用 `/dota` 命令 | `true` |
| `enable_image_output` | 图片回复；关闭后改为返回 Markdown 文档 | `true` |
| `prefer_local_render` | 优先本地渲染卡片（跳过不稳定的网络 t2i），**建议保持开启** | `true` |
| `request_timeout` | API 请求超时（秒） | `15` |
| `cache_ttl_seconds` | 数据缓存时间（秒） | `86400` |
| `steam_api_key` | Steam API Key（可选，用于获取比赛数据） | 空 |
| `enable_llm_summary` | 是否由插件调用本机大模型生成卡片末尾的点评 | `true` |
| `summary_provider_id` | 生成总结的模型（下拉选择），**别选推理模型** | 空 |
| `summary_timeout` | 生成总结的超时时间（秒） | `180` |
| `summary_max_chars` | 点评最大字数，超出时按栏目/句子精简 | `500` |
| `card_theme_preset` | 卡片主题（下拉框四选一） | `light` |
| `enable_replay_summary` | 具体某一局的总结改用**录像解析数据** | `true` |
| `replay_parse_timeout` | 等待录像解析的时长上限（秒） | `720` |

### 卡片主题

主题用一个**下拉框**四选一，不开放逐色自定义（那样太复杂，也容易破坏整卡风格统一）：

| 选项 | 风格 | 主色 |
|------|------|------|
| `light` | **蓝白**（默认）：白底 + 蓝强调，清爽简洁 | 蓝 `#1d4ed8` |
| `dark-gold` | **深色暗金**：近黑暖调底 + 暗金强调，沉稳电竞感 | 暗金 `#c9a227` |
| `pink` | **粉色**：粉底 + 玫红强调，柔和可爱 | 玫红 `#e5538a` |
| `navy-gold` | **深蓝暗金**：深蓝底 `#0a1942` + 暗金标题、正文白色 | 暗金 `#c9a227` |

四套预设的调色板由插件统一维护（`core/card_renderer.py` 是唯一事实源），
**两条渲染路径都生效** —— 网络 t2i 走模板 CSS 变量注入，
本地 Pillow 兜底渲染器同步覆盖，不会出现「换个渲染路径就变色」。
旧配置里的逐色 `card_theme` dict 仍会被兼容读取，但配置页不再暴露。

### 点评模型

`summary_provider_id` 在插件配置页是一个**模型下拉框**，直接选即可，
留空（默认）表示使用**当前会话正在聊天的那个模型**。

#### 关键：不要选推理模型

推理模型的输出预算会先被「思考」（`reasoning_content`）吃掉，
正文可能直接返回**空字符串** —— 插件拿不到总结，就静默退回成
主对话模型的回复文字，用户看到的就是没有数据的定性描述。

麻烦的是**光看名字判断不可靠**：

| 模型 | 名字暗示 | 实际 | 实测表现 |
|------|----------|------|----------|
| `GLM/GLM-4-Flash-250414` | 快 | 非推理 | 9.5 秒，491 字，**推荐** |
| `MC_API/gpt-5.6-luna` | 快 | 非推理 | 10.9 秒，696 字 |
| `deepseek/deepseek-v4-flash` | 快（flash） | **推理** | 思考 9500 字，正文 **0 字** |
| `siliconflow/…/DeepSeek-R1-0528…` | 推理（R1） | **推理** | 88 秒才出结果 |

所以推荐直接用 **`GLM/GLM-4-Flash-250414`**。

> 补充：插件**无法**用 `max_tokens` 给推理模型留输出预算 ——
> AstrBot 的 OpenAI provider 在准备请求时只放 `messages` 和 `model`，
> 多余的参数会被丢弃（实测传入 `max_tokens` 后请求体里并没有它）。
> 想调预算只能改 AstrBot 全局的 `custom_extra_body`，那超出了插件的范围，
> 因此这里的策略是**选对模型**，而不是加参数。

#### 超时时间

`summary_timeout` 默认 **180 秒**，可手动调整。
给到 180 是为了容下推理模型的思考耗时（R1 实测约 88 秒）；
按上面的建议使用非推理模型（约 10 秒出结果）后，可以改小到 `30`，
这样一旦模型不可用能更快回退。

若把 `enable_llm_summary` 设为 `false`，插件就不自己调模型了，
图片底部的总结改用主对话模型本轮的回复文字 —— 但工具并没有把十名玩家的
KDA/经济/经验回传给主对话模型，它只能写出定性判断、列不出数据，
**因此不建议关闭**。

### Steam API Key（可选）

如果 OpenDota 无法获取某些玩家的比赛数据，可以配置 Steam API Key 作为备选数据源：

1. 访问 https://steamcommunity.com/dev/apikey 申请 API Key
2. 在插件管理页面配置 `steam_api_key`
3. 当 OpenDota 返回空数据时，会自动切换到 Valve API

## 数据源

| API | 说明 | 链接 |
|-----|------|------|
| OpenDota API | Dota2 数据查询（玩家、英雄、物品、比赛、实时、职业赛事） | [文档](https://docs.opendota.com/) / [仓库](https://github.com/odota/core) |
| Valve Steam Web API | 备选数据源，当 OpenDota 返回空数据时自动切换 | [文档](https://developer.valvesoftware.com/wiki/Steam_Web_API) |
| AstrBot t2i | 图片卡片渲染（网络优先，本地兜底） | [文档](https://docs.astrbot.app) |

本插件默认使用 OpenDota API 获取数据，无需申请 API Key。如果需要获取比赛数据（当 OpenDota 返回空时），可以配置 Steam API Key 作为备选数据源。

```
core/hero_icons.py         # 英雄名 / 英雄 ID → 官方立绘（卡片左侧头像）
core/icon_cache.py         # 图标与立绘的本地缓存 + data URI 内联
core/templates.py          # 各查询结果的 Markdown 组织
core/card_renderer.py      # 渲染调度：网络优先 + 本地兜底 + 产物校验
core/image_renderer.py     # 本地 Pillow 渲染器（白底主题、字体探测 + 混排）
core/summarizer.py         # 卡片末尾的点评：按查询种类分场景调大模型
tools/delivery.py          # 工具结果交付：暂存卡片到 event，交钩子出图
tools/*_tool.py            # 9 个 LLM 工具
```

### 出图流程

```
LLM 调用工具 → render_*() 生成 Markdown
            → deliver_result() 暂存到 event 附加数据，返回「已出图」提示
LLM 生成最终回复（此文本仅作兜底，不再是主要来源）
            → on_decorating_result 钩子：
                 取回暂存的卡片
                 → summarize()：插件自己调本机大模型写点评
                   （失败/超时/为空 → 回退到 Agent 回复文字）
                 + 「## 综合分析」（对局）/「## 点评」（其余）+ 点评（固定放最后）
                 → 若 enable_image_output 关闭：直接发 Markdown 文本，结束
                 → render_card()（网络 t2i → 本地 Pillow）
                 → 替换消息链为图片
```
